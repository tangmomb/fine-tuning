01_processed

Préparer

Vérifie qu'il y a toutes les bases (correspondances entre les json et les bases SQLite), retire les clés inutiles des fichiers json precedemment cités et ajoute le schéma SQLite. On obtient les 4 jsonl avec les clés suivantes : question_original_en, db_id, sql, schema.

  • 01_check_original_dataset.pycontrôle les JSON et les bases SQLite
  • 02_prepare_english_dataset.pylit les CREATE TABLE dans SQLite et les copie dans le champ schema

Même traitement pour tous les splits.

02_batch

Traduire

Crée et envoie les batches Mistral avec un identifiant par exemple. Cette étape ne fait que préparer et soumettre les requêtes de traduction, elle ne récupère pas les réponses. On envoie dans le prompt la question originale en anglais, le sql attendu pour la question et le schéma SQLite, et on récupère la traduction française.

  • 01_create_and_send_batches.pyprépare et soumet les requêtes de traduction

Pilot : 100 exemples train_spider, en 2 lots. Production : train, train_others, dev et test complets.

03_mistral_response

Récupérer

Télécharge les réponses brutes une fois les batches terminés.

  • 01_download_batch_responses.pyvérifie le statut et télécharge les sorties

Télécharge exactement les lots envoyés dans le mode choisi.

04_translated_fr

Fusionner

Associe chaque traduction à sa question, son SQL et son schéma source. On obtient les 4 jsonl avec les clés suivantes : question_original_en, db_id, sql, schema, question.

  • 01_merge_translations.pyécrit les exemples français complets
  • db_id, question_original_en, schema, sqlrepris depuis 01_processed/*.jsonl
  • questionréponse de 03_mistral_response

Pilot : 100 exemples. Production : tous les exemples des splits traduits.

05_checks

Contrôler

2 juges : 1- Contrôles mécaniques 2- Jugement par gpt 5.6 Sol.

  • 01_check_translations.pyrepère par exemple plus de 56 ans traduit par plus de 55 ans, en 1999 devenu en 2000, un 12 % oublié, ou une réponse qui contient SELECT au lieu d’une phrase française
  • 02_judge_translations.pyrepère par exemple plus de 3 traduit par au moins 3, pas né en Californie sans négation, budget le plus élevé devenu le plus bas, ou un tri par âge oublié

Pilot : juge les 100 exemples. Production : contrôle tout et juge un échantillon, dont le test séparément.

06_fine_tuning_ready

Fine-tuning

Construit les conversations d’entraînement train/dev avec SQL normalisé.

  • 01_build_dataset.pyconstruit train.jsonl et validation.jsonl
route train · dev

Pilot : train_spider seulement. Production : train + validation dev. Le test est exclu.

07_evaluation

Évaluer

Sépare les prompts de test des SQL gold normalisés.

  • 01_prepare_test.pycrée les entrées et gold de test séparés
route test · sans apprentissage

Production uniquement : le test ne sert jamais au pilot ni au fine-tuning.
