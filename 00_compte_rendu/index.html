02 · Point de départ
Tests des modèles bruts
Résultats figés sur les 2 147 requêtes du jeu de test, avant fine-tuning. Les meilleurs résultats Qwen sont indiqués en vert ; GPT-5.6 Luna est présenté comme repère externe.

        

          
    
            
  • Execution accuracy : part des requêtes dont le résultat renvoyé par SQLite est exactement le même que celui de la requête de référence. C’est la mesure principale de la justesse fonctionnelle.
    • 
            
  • Exact match : part des requêtes dont le texte SQL, après normalisation, est identique à la référence. Une requête différente mais équivalente peut donc réussir l’exécution sans compter ici.
    • 
            
  • SQL exécutable : part des requêtes que SQLite peut lancer sur la base concernée sans produire d’erreur. Cela vérifie notamment que les tables, colonnes et types employés sont cohérents avec le schéma.
    • 
            
  • SQL valide : part des sorties dont la syntaxe peut être analysée comme du SQL. Cette métrique ne garantit ni que les noms du schéma existent, ni que la réponse à la question est correcte.
    • 
            
  • Erreurs d’exécution : requêtes syntaxiquement valides, mais rejetées au moment de l’exécution — par exemple à cause d’une table ou d’une colonne inexistante.
    • 
            
  • SQL invalides : sorties qui ne peuvent pas être analysées comme une requête SQL, souvent en raison d’une syntaxe incomplète, d’un format parasite ou d’une réponse en langage naturel.
    • 
            
  • Timeouts : exécutions interrompues parce qu’elles dépassent la durée autorisée, généralement à cause d’une requête trop coûteuse.
    • 
          

        

        

        
Vert : meilleure valeur Qwen de la colonne. Rouge : moins bonne valeur Qwen. GPT‑5.6 Luna est exclu de ces repères.

        

          
Que peut-on conclure ?

          
    
            
  • Sans surprise, la qualité des réponses progresse avec le nombre de paramètres.
    • 
            
  • Le few-shot n’apporte pas de gain robuste sur les modèles Qwen : les améliorations restent marginales sur les plus grands modèles, tandis que les modèles 0,8B et 2B régressent nettement. Il peut donc déstabiliser certains modèles plutôt que d’améliorer fiablement leurs réponses.
    • 
          

        

      


      

        
03 · Expériences de fine-tuning
Adaptations LoRA comparées
Chaque expérience entraîne un adaptateur LoRA sur les 8 651 exemples de train, puis évalue tous ses checkpoints par exécution SQLite sur les 1 034 exemples de validation. Le checkpoint retenu est choisi exclusivement sur cette validation, avant toute évaluation finale sur test.

        
Paramètres du fine-tuning : LoRA (r=16, α=32, dropout 0,05) · 3 époques · learning rate 1e-4 · batch par GPU 2, accumulation de gradients 32, batch effectif 64 · séquences de 3 072 tokens maximum · AdamW avec scheduler cosinus · bfloat16, avec des paramètres de base restaurés en FP32 (36 pour le 2B, 48 pour le 4B)

Pour rappel, nous avions sur les modèles de base :

        
Qwen 3.5 2B : 29,48 % d’execution accuracy, et maintenant sa version fine-tunée :
67,44 %, soit un gain de +37,96 points.
Qwen 3.5 4B : 54,26 % d’execution accuracy, et maintenant sa version fine-tunée :
73,17 %, soit un gain de +18,91 points.
Meilleur score des modèles de base zero-shot : Qwen 3.5 9B avec 63,06 % d’execution accuracy.

        
Que peut-on conclure ?
  • Les gains sont très importants : +37,96 points pour le 2B et +18,91 points pour le 4B d’execution accuracy par rapport à leur version zero-shot.
  • Les deux modèles fine-tunés dépassent le meilleur score zero-shot, celui du Qwen 3.5 9B (63,06 %) : 67,44 % pour le 2B et 73,17 % pour le 4B.

      


      

        
04 · Optimisation LoRA
Explorer les paramètres du Qwen 3.5 2B
La prochaine étape compare différentes configurations LoRA sur le Qwen 3.5 2B. Pour isoler l’effet des hyperparamètres, les mêmes données et le même protocole d’évaluation sont conservés : seule la configuration LoRA varie.

        
Protocole constant : 8 651 exemples train · 1 034 exemples validation · 2 147 exemples test · mêmes bases SQLite, tokenizer, prompts, nombre d’époques, learning rate, batch et procédure de sélection sur validation

        
Paramètres LoRA à explorer : rang (r), facteur d’échelle (α) et dropout.
